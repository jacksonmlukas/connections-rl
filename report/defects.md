## Open (design constraints, not errors)

**D5. The k=16 sampling pool cannot support any other k, for any metric —
binary or graded.** The per-puzzle record schema in
`results-analysis/passk-{7b,1.5b}.json` is `puzzle_id, date, any_solved,
any_valid, max_groups_correct, best_reward, n_samples`. Every outcome field is
an aggregate over the 16 samples: `any_solved` and `any_valid` are booleans
(an OR), `max_groups_correct` and `best_reward` are maxima. The unbiased
pass@k estimator needs the per-puzzle success *count* `c`, and a boolean OR
does not recover `c` — so the binary solve and validity curves are just as
unrecoverable from this pool as the graded groups curve, which additionally
needs the per-sample score multiset. Nothing below k = 16 is salvageable from
the existing pool for any metric, and k = 32 requires n ≥ 32 fresh samples.
`eval/passk_curve.py` regenerates a pool that persists every per-sample
outcome; plan in `passk-curve-runplan.md`.

**D6. Sampling-session settings are only partially recorded.** The passk JSONs
record `k` and `temperature` (0.9) but not `top_p`, the vLLM version, or the
serving layout. Consistent with the run plan's recommendation: regenerate all
three arms in one fresh serving session rather than mixing the recovered pool
with new samples.

**D7. TRL version unpinned (pre-existing, tracked in
`implementation_notes.md`).** The `scale_rewards`/`loss_type` defaults were
inherited from the installed TRL version, which was not pinned per run. Already
flagged there as an action item; restated here so the defect list is complete.
